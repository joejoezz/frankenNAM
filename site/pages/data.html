Get Operational Data

The NAM's grid-218 awphys files, under the operational file names, so the tools you already have work by swapping the base URL.

What is available

  • GRIB2 mirror of grid 218 awphys, NOAA-identical names and paths: 
    nam.YYYYMMDD/nam.tCCz.awphysFF.tm00.grib2
nam.YYYYMMDD/nam.tCCz.awphysFF.tm00.grib2.idx
    f00 to f84 every 3 h, for the 00Z and 12Z cycles; one GRIB2 and one .idx per hour (454 records, as the operational file). Byte-range reads from the .idx work as they do on NOMADS.
  • Icechunk / Zarr store of the same fields, for Python users. Coming soon

These are FrankenNAM files, not the operational NAM's: initialized from the (C−6)Z GFS analysis with a 6 h NAM spin-up; no observations after (C−6)Z. Read Validation first. Status and file checksums for each cycle are published beside the files.

Swapping it into your tools

Only the base URL changes. KEY is your subscription key; it sits in the URL path and is removed at the edge. Host name and paths are the plan, not yet live.

curl: one file, or one field by byte range

BASE=https://grids.theconvergencezone.com/$KEY/nam.20261102
F=nam.t12z.awphys24.tm00.grib2

# the whole file and its inventory
curl -s -O "$BASE/$F" -O "$BASE/$F.idx"

# only the 2 m temperature message: offsets come from the .idx
R=$(curl -s "$BASE/$F.idx" | awk -F: -v pat=':TMP:2 m above ground:' \
      '$0 ~ pat {s=$2; if ((getline) > 0) print s "-" ($2-1); else print s "-"; exit}')
curl -s -r "$R" "$BASE/$F" -o t2m.grib2

wgrib2

wgrib2 "$F" -match ':(TMP|DPT):2 m above ground:' -csv t2m_td2m.csv
wgrib2 "$F" -s | head

Python, Herbie

import urllib.request, eccodes as ec
base = "https://grids.theconvergencezone.com/KEY/nam.20261102/nam.t12z.awphys24.tm00.grib2"
rows = [l.split(":") for l in urllib.request.urlopen(base + ".idx").read().decode().splitlines()]
i = next(k for k, r in enumerate(rows) if r[3] == "TMP" and r[4] == "2 m above ground")
end = int(rows[i + 1][1]) - 1
req = urllib.request.Request(base, headers={"Range": f"bytes={rows[i][1]}-{end}"})
g = ec.codes_new_from_message(urllib.request.urlopen(req).read())

? how the .idx works
Each line is n:offset:d=YYYYMMDDHH:VAR:level:step:. A message runs from its offset to the byte before the next line's offset. The curl and awk steps were tested against a local copy of the files; the HTTPS host does not exist yet.
