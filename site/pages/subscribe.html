How access works

You receive a key after checkout. The key goes in the URL path, so every tool that can fetch a URL works unchanged:

https://grids.theconvergencezone.com/<key>/nam.YYYYMMDD/nam.tCCz.awphysFF.tm00.grib2
https://grids.theconvergencezone.com/<key>/nam.YYYYMMDD/nam.tCCz.awphysFF.tm00.grib2.idx

The key is stripped at the edge and is not part of the file's path. Treat it like a password: it identifies your subscription, and one that is shared widely may be switched off.

Swapping it into your tools

The only change is the base URL. File names, the .idx layout and the grid (218, 12 km Lambert conformal) are the operational NAM's.

wgrib2

Fetch a file, or only the messages you need using the .idx byte ranges, then read it as usual:

BASE=https://grids.theconvergencezone.com/$KEY/nam.20261102
F=nam.t12z.awphys24.tm00.grib2
curl -s -O "$BASE/$F" -O "$BASE/$F.idx"
wgrib2 $F -match ":(TMP|DPT):2 m above ground:" -csv t2m.csv

For a single message, read its offset and the next one from the .idx and send curl -r START-END. That is how the free maps read the files.

Python and Herbie

Any code that reads GRIB2 from a URL needs only the new base. With .idx byte ranges in plain Python:

import urllib.request
base = "https://grids.theconvergencezone.com/KEY/nam.20261102/nam.t12z.awphys24.tm00.grib2"
idx = urllib.request.urlopen(base + ".idx").read().decode().splitlines()
# pick lines for the fields you want, then request base with a Range header
# for each line's offset up to the next line's offset

Before you pay

  • FrankenNAM is initialized from the (C−6)Z GFS analysis with a 6 h NAM spin-up and has no observations after (C−6)Z, where C is the cycle time (the 12Z cycle starts from the 06Z analysis). It is not the operational NAM.
  • Read the scorecard for how it has done against observations, and the terms for what you are agreeing to.
  • Monthly billing means the most you can lose to a service that stops is one month.
